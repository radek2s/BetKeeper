## Objective

Validate that a can convert verbal bet into digital record without assistance in mobile environment with mild distractions.

This protocol verifies the following requirements:

- [BKR_01](../../01_requirements/00-requirements.md) - Platform for noting bets
- [BKR_02](../../01_requirements/00-requirements.md) - Establishing bets regardless of distance and location
- [BKR_03](../../01_requirements/00-requirements.md) - Creation of bet request
- [BKR_04](../../01_requirements/00-requirements.md) - Selecting friend to participate bet
- [BKR_12](../../01_requirements/00-requirements.md) - Resolve bet
- [BKR_27](../../01_requirements/00-requirements.md) - Mobile friendly
- [BKR_28](../../01_requirements/00-requirements.md) - Application in sync

## Scenario context
_Copied from BKUS-2_

You were at a bar with a friend, and he made a spontaneous bet that you wouldn’t arrive at your bus stop on time. You managed to make it, and now you’re sitting on the bus heading home. You want to quickly record the result of this bet using BetKeeper so the outcome is saved and your friend can see it later. You are using your smartphone and expect the process to be simple and fast.

## Preconditions

- Participant has access to BetKeeper on a smartphone with Internet access
- Participant has a friend with who he will be able to create a bet request
- Participant is seated and holding the phone in one hand (simulating the bus environment)
- Participant is not given instruction about the UI or steps.

## Tasks

### Task 1: Create a new bet
Success criteria: User created a valid bet with stakes, terms and claims with his friend

### Task 2: Bet marked as resolved
Success criteria: User marked bet as resolved. 


## Success criteria

- User completes all tasks without assistance
- There is no critical errors during execution
- User has defined bet with individual stake

## Metrics

| Task completion rate | >= 90% | Across all participants |
| Time on task | <= 10 minutes | From start to resolved bet  |

- User confidence rating: 1 - 5

## Error classification

### Critical errors:
- User cannot create bet request
- User abandons the task

### Non-critical errors:

- Misclicks
- Opening wrong screen but recovering
- Confusion about terminology
